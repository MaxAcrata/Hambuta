### 2.1 Confirm the API surface (signatures, not names)

Via **ValheimGameLibs NuGet + Mono.Cecil** (no game needed) and/or `ilspycmd` on `assembly_valheim.dll`. Record each hit with declaring type:

| API | Signature to confirm | Used for |
|---|---|---|
| Instantiate | `PrefabManager.GetPrefab(string) → GameObject`; `Object.Instantiate(GameObject, Vector3, Quaternion)` | create instance |
| Identity | `Character.GetZDOID() → ZDOID`; `ZNetView.GetZDO() → ZDO` | stable id |
| Tame | `MonsterAI.MakeTame()` **or** `Tameable.Tame()` (AccessTools) **or** ZDO `s_tamed` | make companion |
| Command | `Tameable.Command(Humanoid user, bool message)` *(not GameObject)* | follow/stay |
| Move | `MonsterAI.SetFollowTarget(GameObject)` / `GetFollowTarget()` | the one move method |
| Pin (fallback action) | `BaseAI.SetPatrolPoint()` no-arg | alternate observable action |
| Stop | `BaseAI.StopMoving()` | cleanup |
| State | `GetHealth()`, `IsTamed()`, `IsDead()`, `m_faction`, `m_name`, `m_baseAI` | diagnostics |

If a symbol is missing in the live DLL, record it and adjust — **never code against an unconfirmed name**.

### 2.3 Confirm creation & component initialization order (the real sequence)

Pseudo-order to implement and then **prove in Stage 4** (each step logged; fail-fast with reason):

```
1. Preconditions
   - Player.m_localPlayer != null
   - ZNetScene / ObjectDB ready (Jötunn events already fired)
   - prefab = PrefabManager.GetPrefab(cfg.PrimaryPrefab)  // else cfg.FallbackPrefab
   - prefab != null && has ZNetView

2. Instance
   - pos = player.transform.position + player.forward * 2f + Vector3.up
   - go = Object.Instantiate(prefab, pos, Quaternion.identity)
   - nview = go.GetComponent<ZNetView>()
   - if nview == null || !nview.IsValid() -> ERROR "no network identity"

3. Component init (order matters)
   a. character = go.GetComponent<Character>() / Humanoid   (required)
   b. monsterAI = go.GetComponent<MonsterAI>()
      - if null and Humanoid exists -> AddComponent<MonsterAI>()  // only if Stage 2 says safe
      - if still null -> REJECT candidate
   c. baseAI = character.m_baseAI or GetComponent<BaseAI>()     (must be non-null)
   d. faction: character.m_faction = Character.Faction.Players
   e. tameable = go.GetComponent<Tameable>()
      - if null -> AddComponent<Tameable>() only when Humanoid+MonsterAI exist
      - tameable.m_commandable = true
   f. tame:
      - prefer monsterAI.MakeTame()
      - else AccessTools Tameable.Tame()
      - else ZDO zdo.Set(ZDOVars.s_tamed, true)  // only if nview.IsOwner()
   g. merchant neutralize (if Trader/Offerings present):
      - disable interact component OR mark candidate as "caveat" / reject
   h. verify:
      - character.IsTamed() == true  (or zdo s_tamed)
      - m_faction == Players
      - m_commandable == true
      - GetZDOID() != empty

4. Register in controller
   - store ZDOID + GameObject handle
   - log identity block (vc state format)
```

**Failure policy:** any step can fail; log `step N failed: reason`; try fallback prefab once; if both fail → Stage 2/4 report "no viable candidate", do not fake an NPC.

### 2.4 Merchant / special-AI caveats (Haldor, Hildir)

- Human traders are **not** MonsterAI companions by design. Verifying them means answering:
  1. Can `MonsterAI` coexist with `Trader`/`Offerings` without exceptions?
  2. Does E-key open shop instead of follow/command? If yes, can we disable that on the instance?
  3. Does the merchant despawn or ignore `SetFollowTarget`?
- **Verdicts allowed:** `works`, `works with caveat (name it)`, `rejected (name the failing member)`.
- Never ship Haldor as "the companion" just because it looks human.

## Stage 5 — One controlled action (single move method)

**Start with ONE method only** (per priority #3). Choose at Stage 2/4 based on what the chosen NPC actually supports:

**Default pick: `MonsterAI.SetFollowTarget(markerGO)`** — fewest moving parts, proven in local KB.  
*(If Stage 2 shows the candidate cannot follow, fall back to `SetPatrolPoint(dest)` pin — still one method.)*

**Do not implement the precise `MoveTo` driver in this stage.** It can be a later iteration after acceptance.

**Actions:**
1. Record **before** state (position, distance to dest).
2. Issue command (`vc move here` / `vc move x y z`).
3. Poll distance every 0.5 s.
4. **Success** = distance ≤ threshold for 2 polls (if Follow: **3.5 m**, because vanilla stop is 3 m).
5. **Timeout** 30 s (cap 60 s) with diagnostics: final distance, `IsAlerted`, `IsSwiming`, follow target.
6. Record **after** state; cleanup (`StopMoving()`, clear target, destroy marker).
7. If this NPC cannot move: pick another *single* observable action (pin via `SetPatrolPoint()`) and **document the limitation** — never fake success.

**Critical criterion:** command → **observable game-state change** (distance shrinks / position changes), not just a log line.  
**Exit criteria:** before/after recorded; success or honest timeout; errors handled.

## Diagnostic commands (priority #5)

**Invocation path:** Jötunn `CommandManager` + `ConsoleCommand` subclasses, registered in `Plugin.Awake`.

| Command | Effect |
|---|---|
| `vc spawn` | spawn companion (Stage 2 primary prefab) |
| `vc spawn fallback` | spawn using Stage 2 fallback |
| `vc state` | dump 10-field state block to console + BepInEx log |
| `vc move here` | move to player position (the **one** method) |
| `vc move <x> <y> <z>` | move to coordinates |
| `vc status` | move-job: Pending / Running / Succeeded / TimedOut / Aborted + distances |

**Console access requirements (documented in README):**
1. Steam launch option **`-console`** (F5 otherwise does not open).
2. In console: **`devcommands`** first for vanilla cheats (`pos`, `printcreatures`, `spawn`, `tame`) — **local host / single-player only**.
3. Our `vc *` commands are registered via Jötunn and work whenever the plugin loaded; they should also accept a `Terminal` context and print with `context.AddString()`.

**Cross-checks with vanilla:** `pos`, `printcreatures`, `find` — to prove our logs match the game.

## Universal seam + future MiMo (priority #4 — design only)

```
Core/
  ICompanionEntity.cs    # state DTO
  IGameAdapter.cs        # Spawn / GetState / RequestMove / Tick
```
